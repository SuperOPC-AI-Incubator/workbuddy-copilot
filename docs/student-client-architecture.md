# 学员端客户端架构：本地代理 + 可替换壳

**状态**：设计已定，本期只实现代理侧（无 UI）
**日期**：2026-07-26

## 为什么需要这份设计

学员端要一个"不用开着网页也能被叫到"的常驻界面（浮标或托盘）。但现成的两个候选实现
（macOS PyObjC 浮标、未测试的 Windows Python 浮标）都**自带一整套网络与状态逻辑**：
WebSocket 客户端、REST 调用、回执账本、去重窗口、重连退避。

而学员机上已经有一个 connector 在做同样的事，并且它的实现经过并发压测（outbox 原子
落盘、claim 锁、lease 心跳、409 隔离、fetch-before-ack）。

**两个进程各自 fetch 和 ack 同一批导师消息 = 重复拉取、ack 竞态、一个显示了另一个去
确认。** 服务端还有数据库级的 fetch-before-ack 约束，冲突会表现为消息被移进 quarantine
或回执状态错乱 —— 都是静默的。

这不是配置问题，是架构问题。必须先划边界。

## 分层

```
                    云端（Supabase + Node 服务）
                              ▲
                              │ HTTPS（唯一出口）
                  ┌───────────┴────────────┐
                  │   本地代理 (connector)  │
                  │                        │
                  │  独占：凭证、网络、     │
                  │  outbox、render ledger、│
                  │  ack、重连退避、去重     │
                  └───────────┬────────────┘
                              │ 本地 IPC（本文件定义的契约）
                    ┌─────────┴─────────┐
                    │                   │
              ┌─────▼─────┐      ┌──────▼──────┐
              │  壳 / UI  │      │  壳 / UI    │   ← 纯展示层，可替换
              │  (未来)   │      │  (未来)     │
              └───────────┘      └─────────────┘
```

**铁律：壳不碰网络，不碰凭证，不维护投递状态。**

壳只做三件事：显示代理给它的东西、把用户动作转成 IPC 请求、告诉代理"这条已经展示给
人看了"。

### 这条边界带来什么

|          | 收益                                                                           |
| -------- | ------------------------------------------------------------------------------ |
| 凭证     | 只存在代理的私有配置（0600 / Windows ACL）。壳永远看不到 token，被逆向也拿不到 |
| 可靠性   | 投递语义只有一份实现，不会两套逻辑互相打架                                     |
| 壳可替换 | 先用什么做壳、以后换什么，代理与云端都不用动                                   |
| 多壳并存 | 允许同时有托盘 + 浮标，甚至一台机器多个 UI；代理是唯一权威                     |
| 可测试   | 壳可以用假代理测，代理可以用假壳测，不必启动 GUI                               |

## 技术选型：壳用 Node

已定：**壳走 Node 技术栈**，不用 Python。

理由不是"Python 不行"（PyInstaller 确实能编译成可执行文件），而是：

1. 代理已经是 Node，学员机上的运行时问题已经解决（用 WorkBuddy 自带的 Electron 作
   解释器，实测 node 22.21.1，零安装）。壳同栈可以复用同一运行时策略
2. 云端网页是 React，壳如果最终要有界面，组件与数据层可以共享
3. Python 路线要维护两套 UI 代码库（PyObjC + Windows 那套），且 macOS 需签名公证、
   Windows 的 PyInstaller 产物被杀毒误报是高频事件

**本期不做 UI。** 只把代理侧的 IPC 实现出来，壳留给未来。届时按需选：

| 形态                      | 额外安装                       | 适用                       |
| ------------------------- | ------------------------------ | -------------------------- |
| 无界面后台进程 + 系统通知 | 0（复用现有运行时）            | 只要"别漏消息"             |
| 托盘小程序                | 几百 KB 的壳（为拿到通知身份） | 要品牌化通知、未读数       |
| Tauri 浮窗                | ~10MB                          | 要常驻窗口、就地回复       |
| Electron 浮窗             | ~100MB                         | 同上，且要最大化复用 React |

**先做最左边、验证需求，再决定往右走多远。** 契约不变，壳是可替换件。

## 本地 IPC 契约

### 传输

- **POSIX**：Unix domain socket，位于代理私有状态目录，权限 0600
- **Windows**：命名管道，DACL 仅当前用户
- **不使用 TCP 端口** —— 本机其他用户/进程可连，且要额外管鉴权

同一用户会话内的进程才能连上，靠文件系统/管道权限而非应用层 token 保证。

### 协议

行分隔 JSON（NDJSON），请求-响应 + 服务端推送混合。每条消息一行。

```
请求:  {"id":"<uuid>","op":"<操作>","params":{...}}
响应:  {"id":"<同上>","ok":true,"result":{...}}
       {"id":"<同上>","ok":false,"error":{"code":"...","message":"..."}}
推送:  {"event":"<事件名>","data":{...}}
```

### 操作（壳 → 代理）

| op                   | 用途                                         | 关键约束                                           |
| -------------------- | -------------------------------------------- | -------------------------------------------------- |
| `hello`              | 握手，返回代理版本与能力清单                 | 壳必须先握手；版本不兼容时代理明确拒绝，不静默降级 |
| `status`             | 队列深度、连接状态、凭证是否已配置、最近错误 | 供壳显示健康状态，不含任何凭证内容                 |
| `messages.pending`   | 取尚未展示的导师消息                         | **只读**。不触发网络，不改变服务端状态             |
| `messages.displayed` | 声明某几条已经展示给人看了                   | 代理据此驱动 ack；**壳不直接 ack**                 |
| `subscribe`          | 订阅推送                                     | 见下                                               |

### 推送（代理 → 壳）

| event            | 时机                             |
| ---------------- | -------------------------------- |
| `message.new`    | 代理拉到新的导师消息             |
| `status.changed` | 连接状态、队列深度、凭证状态变化 |
| `agent.shutdown` | 代理即将退出，壳应显示离线态     |

### 为什么 ack 必须由代理驱动

服务端有数据库级的 fetch-before-ack 约束，代理侧有 lease 保护的 render ledger。壳只
上报"我展示了"这个**事实**，由代理决定何时、以什么顺序、失败后如何重试地向服务端确认。

壳可能崩溃、可能被强杀、可能同时跑两个 —— 这些都不能破坏投递语义。把 ack 留在代理
是唯一能保证这一点的方式。

### 契约的兼容性规则

- `hello` 里的能力清单是唯一的协商入口。壳按能力开关功能，**不按版本号猜**
- 新增字段允许；删除或改变既有字段语义视为破坏性变更，必须提升协议版本
- 代理遇到不认识的 `op` 返回 `UNKNOWN_OP`，不静默忽略（静默忽略会让壳以为成功）

## 云端需要补的能力

壳能做什么，受限于云端对 `wb_` 凭证开放了什么。当前只有三个公有端点：`ingest`、
`mentor-messages`、`mentor-messages/ack`。其余全部要求 Supabase 登录态。

| 缺口                     | 影响                                                         | 本期做吗               |
| ------------------------ | ------------------------------------------------------------ | ---------------------- |
| **每轮对话自动 AI 诊断** | 壳没有内容可显示 —— 只能提示"有新消息"，那浏览器通知已经能做 | **做**（见下）         |
| `wb_` 可用的问答端点     | 壳只能看不能问                                               | 设计好，等壳存在再实现 |
| `wb_` 可用的能力查询     | 壳无法显示"AI 当前可用/不可用"                               | 同上                   |
| 实时推送给 `wb_` 持有者  | 代理只能轮询；延迟 = 轮询间隔                                | 暂不做，轮询够用       |

### 每轮自动 AI 诊断（本期实现）

这是产品场景明确要求的："学员跟 AI 的对话，AI 可以进行分析并提供建议，学员和导师都
能看到。"云端目前完全没有 —— `ingest` 只存原文，`diagnosis` 字段是客户端可选传的。

设计：

- 触发点：`ingest` 成功落库**之后**，异步执行，**绝不阻塞 ingest 的响应**
- 输入：该轮的 prompt + reply（已脱敏），以及同会话最近若干轮的有界上下文
- 输出：写入 `timeline_items`，`kind='diagnosis'`，带 `severity`（ok/warn/error）与
  可选 `tag`。表结构现成，无需迁移
- 并发：限流，避免 45 个学员同时上报时把 LLM 配额打满
- 失败：诊断失败**不得**影响该轮对话本身的落库；记录可观测的失败计数，不重试到死
- 幂等：同一 `event_id` 只产出一条诊断；重复 ingest（duplicate）不重复生成
- 成本可控：可配置开关与采样率 —— 不是每轮都必须诊断，密集操作时可降频

## 明确不做的事

- **不做 UI**。本期只到"壳可以接上来"为止
- **不把 Python 浮标接进来**。若未来复用，也必须先剥掉它自带的网络与回执逻辑，只留
  纯展示部分 —— 那部分才是它真正不可替代的资产
- **不引入 TCP 本地端口**
- **不让壳持有凭证或 Supabase 会话**
- **不为壳新增服务端实时推送**（轮询够用，且实时会把 Supabase JWT 引入壳）

## 已知风险

1. **多壳同时连接**：契约允许，但 `messages.displayed` 的语义是"人看到了"。两个壳都
   显示同一条时会重复上报 —— 代理必须按消息 ID 去重，而不是按连接
2. **壳崩溃在"已显示但未上报"之间**：这条消息会被再次投递。at-least-once 是刻意选择，
   重复展示比丢失可接受
3. **代理未运行**：壳必须能明确显示"代理离线"，而不是空白界面装作正常
4. **诊断的成本与噪音**：每轮都跑 LLM 有配额与打扰成本，需要采样与阈值，且导师端要能
   区分"AI 说的"和"导师说的"（`kind` 已经区分）
